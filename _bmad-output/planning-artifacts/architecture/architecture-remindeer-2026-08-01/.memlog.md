- (decision) AD: landing page tree (hero, comparison, footer, static preview card) stays Server Components by default. 'use client' boundary drawn only around quiz flow and final-screen feedback/email form, not the whole page. Prevents: whole-page client-component bloat; inconsistent boundary placement per contributor.
- (decision) AD: analytics events fired only through a single track(event, props) wrapper with a fixed event-name list (visit_landing, quiz_started, quiz_completed, etc per FR-12), never ad-hoc Plausible/Umami calls from components. Prevents: divergent event naming between landing and quiz code paths.
- (decision) AD: DESIGN.md tokens (colors, type, spacing, radii) wired as Tailwind v4 theme.extend, consumed as ordinary utility classes. No CSS custom properties / arbitrary-value token access pattern. Prevents: two parallel token systems (Tailwind config vs CSS vars) drifting out of sync.
